## 5. What's actually next

**Recommendation: close the Group I ownership-isolation gap before starting any Phase 4 work.**

Phase 3's backend groups are, on the evidence, essentially complete — A through J are Done or Done-with-a-flagged-caveat, with one Partial (I). The plan itself names ownership isolation "exhaustive, not spot-checked" as one of the two most important things to verify in the whole test suite, and this audit found it is currently spot-checked: only `workout_sessions` has an explicit cross-user `FORBIDDEN` test on push, while `exercises` and `workout_templates` have the same guard in source but no test proving it holds. This is:

- Cheap to close — the pattern to copy (`SyncPushTest`'s existing cross-user-rejection test for sessions) already exists and just needs two more entity-type variants.
- Security-relevant, not cosmetic — it's the exact property that stops one user from overwriting another's data through the sync endpoint.
- The kind of gap that's easy to lose track of exactly because everything else around it looks done, which is the same failure mode this whole report exists to correct for.

Secondary, lower-urgency items worth queuing behind it: the Group F literal three-way-batch test, the Group A Kotlin-codegen-in-CI gap (relevant the moment Phase 4 Android work starts consuming the generated client), and a decision on how the OWASP/Sonar CI work should be recorded. Starting Phase 4 Android sync work now would be premature given the open, named test gap in Phase 3 — but the backend itself is not what's blocking Phase 4 from starting once that gap closes.
