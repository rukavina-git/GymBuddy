# Council 2026-11-01: what tapping the Progress chart opens

## Brief
```
COUNCIL BRIEF: what tapping the Progress chart opens (GymBuddy, native Android, Soft Dark redesign)
Decided: Progress tab = counts line / ONE chart card: one lift's best (heaviest) set per session over time, e.g. "Bench press: 80 -> 87.5 kg in 8 weeks", sparkline, "Show as table" / last 5 sessions / "All sessions" (with search). Previous council said: the chart card opens a "Stats" screen that grows over versions (v2 records, v3 more charts, v4 body weight). An even earlier council said: per-exercise progress ("my bench over time") lives on the exercise detail page, and Progress links to it (one chart, built once).
Owner's view: a chart signals "history and progress" of a lift, not one workout session. A veteran suggested "tap a point on the chart opens that session". Owner is unsure; maybe tapping should open the bench (exercise) overview instead.
Q1. Tapping the chart CARD on Progress opens:
 (a) a Stats hub screen: the big lift chart + "Change lift" + later sections (records, other charts, body weight)
 (b) that exercise's detail page (Bench press), scrolled to its Progress section (big chart, best sets, history of that lift)
 (c) both exist: card opens exercise detail; Stats hub is reached separately (e.g. "All stats" link or top-bar action on Progress)
 (d) card opens Stats hub; inside it, the lift's name links to exercise detail
Q2. On the BIG chart (wherever it lives), tapping a single point:
 (a) shows a tooltip (date, 87.5 kg x 5) with an "Open session" link
 (b) opens that session directly
 (c) tooltip only, nothing opens
 (d) points are not interactive; "Show as table" rows (date, set) are tappable and open the session
Q3 (short). Where does "Change lift" live: on the card, in Stats, on the big chart, or not needed (each exercise detail has its own chart)?
Constraints: Operate mode, M3, system Back, WCAG AA, TalkBack (charts need text equivalents), 48dp targets (a chart point is tiny), font 200%. Lime = pressable, cobalt = you are here. Design only, no API/Room change. Keep the number of screens low; every screen must earn its place.
Read: PRODUCT.md, docs/plans/figma-foundation/design-brief.md, docs/council/2026-11-01-progress-contents.md, docs/council/2026-11-01-progress-layout.md. Repo /Users/karlo/Dev/GymBuddy. Do not edit files.
```

## Answers (condensed, votes verbatim)

### Design director (impeccable)
VOTE: Q1 (b), Q2 (d), Q3 "Change lift" chip on the card; exercise detail needs none.
- Earlier council: chart lives on the exercise, built once. A v1 Stats hub repeats it and doesn't earn a screen (Operate: known patterns over invented structure). Hub at v2 when records exist = (c) later.
- Owner reads the chart as "this lift's history": tap goes to the lift, not a session.
- android.md 48×48dp + 8dp spacing: chart points fail; table rows are 48dp+ and are the text equivalent.
- critique.md cognitive load: chart is the glance, table is the action.
RISK: veterans expect to scrub; chart can feel dead. Fix: "Tap a row to open the session" above the table.
VETO: Q2 (b) tiny target that navigates with no preview.
IDEA: "Show on Progress" toggle (pin the lift) in each exercise's Progress section; the card chip is a shortcut to it.

### Product owner
VOTE: Q1 (b), Q2 (d), Q3 overflow "Change lift" on the card + "Show on Progress" on exercise detail.
- Exercise detail exists in v1; no new screen. Hub with one chart doesn't earn its place.
- Grows to (c): add Stats hub only when it has more than one real thing, linked from the Progress top bar. Plan 3 designs the slot, doesn't build it.
- Table rows are real targets and the text equivalent; session detail is reused.
RISK: exercise detail gets long; landing scrolled to Progress can disorient; Back must return to Progress.
VETO: Q1 (a) in the first build.
IDEA: "Show on Progress" pins the lift; no picker screen needed.

### Android architect
VOTE: Q1 (b), Q2 (a), Q3 picker chip on the card.
- NavRoutes.ExerciseDetails (exercise_details/{exerciseId}) exists; scroll to Progress via a route arg. Hub = new route + VM with nothing in it.
- One chart composable: small on the card, big on exercise detail.
- Q2 (a) cheap: pointerInput snaps a tap anywhere in the plot to the nearest x, so no 48dp problem; Popup tooltip with "Open session"; table rows open the same session for TalkBack.
- No SessionDetail route today; All sessions needs one anyway.
RISK: ExerciseDetails reads from a full-list VM; the chart needs its own VM + query by id (Plan 4).
VETO: Q2 (b).
IDEA: sessionId arg; Back returns to the chart with the selected point kept in SavedStateHandle.

### Accessibility / gym ergonomics
VOTE: Q1 (b), Q2 (d), Q3 "Change lift" chip on the card only (48dp, TalkBack custom action).
- One chart, one TalkBack summary and table. Hub with one chart hasn't earned its place.
- ~8dp points fail with sweaty thumbs; touch-only tooltips are invisible to TalkBack.
- Table rows ≥72dp, plain text, work at 200%.
- Back from exercise page returns straight to Progress.
RISK: sighted veterans tap points and nothing happens; keep "Show as table" visible, highlight latest row.
VETO: Q2 (b).
IDEA: whole chart one TalkBack stop: "Bench press best set, 8 sessions, 80 to 87.5 kg, up 7.5 kg. Double-tap for table." Actions: Change lift, Open exercise.

### Beginner lifter
VOTE: Q1 (b), Q2 (d), Q3 not needed on the card; a "See other lifts" link to the exercise list.
- Tap "Bench press", see bench press. A Stats hub sounds like a dashboard; I'd freeze.
- Exercise page already has photos, notes, history: one place to learn.
- Shaky hands: big table rows, not dots.
RISK: exercise page long; Progress section never found.
VETO: Q2 (b): accidental dot tap opens an old workout and I'm lost.
IDEA: plain sentence above the chart: "You lift 7.5 kg more than 8 weeks ago." Also the TalkBack text.

### Veteran lifter
VOTE: Q1 (b), Q2 (a), Q3 lift picker chip on the card.
- Changed my mind: tap-opens-session is wrong; 8dp point, mis-taps. Tooltip first, then "Open session".
- "Is my bench moving?" belongs on the bench page (Strong, Hevy do this). Build once.
- Hub with one chart doesn't earn a screen; add when records/body weight ship.
- Keep table rows tappable too.
RISK: picker chip adds a control to a calm card.
VETO: Q2 (b).
IDEA: scrub: press and drag, tooltip snaps to the nearest point.

Q1 unanimous (b): the card opens that exercise's page, at its Progress section. No Stats hub in the first build; it arrives (v2+) when records exist, linked from the Progress top bar (option c later).
Q2: 4 d (points not tappable; table rows open the session), 2 a (tooltip). Everyone vetoes (b). Middle ground: scrub/tap anywhere on the plot shows a value tooltip (no navigation, snap to nearest point, so no tiny targets); only table rows navigate.
Q3: "Change lift" chip on the card (4); impeccable + PO add a "Show on Progress" pin on each exercise page.
Ideas: plain sentence above the chart ("You lift 7.5 kg more than 8 weeks ago"), one TalkBack stop with full summary, highlight latest table row, Back keeps the selected point.
Recommendation: Q1 (b); Q2 (d) + scrub-to-read tooltip without links; Q3 chip on card + "Show on Progress" pin on exercise detail.

Owner (2026-11-01): accepted as recommended. Card opens the exercise page at Progress; no Stats hub until v2+; points not tappable, drag shows a value tooltip, table rows open the session; "Change lift" chip on the card + "Show on Progress" pin on exercise page; plain sentence above the chart.
